## 0. 验收规程(每页一次,不许跳)

1. **同一份数据**:两边都连 `.tmp/device/EMMC Images`(离线镜像)。
   除「设备管理」「扫描设备」外,不依赖在线 ASIAIR。
2. **同一个窗口尺寸与位置**:先 `MoveWindow` 到 `(0,0)`、`1760x1100`,再截图。
   窗口部分在屏幕外时截出来的东西**看起来像布局塌了** —— 这条踩过。
3. **换个人来验**:验收的人不能是写这一页的人 —— 写的人知道自己想画什么,
   于是会看见自己想画的东西。验的人只拿到本文件里那一页的清单,
   自己启动两套界面、自己截图、自己逐条对照。
4. **证据留档**:两张截图落在 `docs/evidence/qt/<页>-old.png` 与
   `<页>-qt.png`,交互类的再加 `<页>-qt-<动作>.png`。**证据不留就不算验收。**
   (这些图有 200 MB 出头,全是真机截屏,**不随发布出去** —— 下文提到的
   文件名是留在这里的索引,不是仓库里应该有的文件。)
5. **判据**:
   - **功能**:清单里每一条操作在两边都要能做,结果一致(数字、排序、跳转)。
   - **视觉**:整体版式、分栏比例、信息分组、层次一致。配色不要求一致
     (Qt 这套是深色 + 红光 + 白天三档),但**信息密度与位置**要一致。
6. 任何一条不过 → 记在那一页的「未过」栏,修完重跑整页,不做局部补验。

### 启动命令(两边)

```bash
# 老 UI(WinUI3)
ASTRO_SMB_HOST="<镜像目录>" ASTRO_SMB_GUI_TITLE_TAG=OLDREF \
ASTRO_SMB_GUI_START_PAGE=<页> ASTRO_SMB_GUI_AUTOCLOSE=60 uv run astro-smb-tool-gui

# Qt
ASTRO_SMB_QT_TITLE_TAG=QTREF uv run --with pyside6 python -m astro_smb_qt \
  --host "<镜像目录>" --page <页> --seconds 60
```

Qt 侧另有 `--browse "共享/路径"`、`--select N|fit`、`--auto`,验收时用它们
把界面开到同一个状态,避免"两张截图其实不在比同一件事"。

## 11. 假数据驱动:那 6 条「离线镜像触发不到」的

### 这几张图证明什么、不证明什么

## 附:§10 那两条的说明

> ### 10.3「边栏分组」是**有意偏离**,不是漏做
>
> 验收员逐项核对了三套前端:**顺序**(浏览→拍摄记录→导星分析→3D 天球→
> 影像查看→空间分析→设备管理→扫描设备→传输)与**文案**(连图元符号
> `▣▤◈◉◍▦◫⌕⇅` 都一样)与老 UI `main.xaml`、Uno `ui/shell.py` **逐字一致**。
>
> 差的是**分组**:Qt 把九项分成「数据 / 影像 / 设备」三个带标题的分区,
> 而老 UI 是平铺九项、Uno 也是单层循环渲染。按清单原文"与另外两套一致"
> 逐字读,这一半对不上。
>
> **保留分组,并在这里记一笔**,理由:顺序与文案没动(肌肉记忆不受影响),
> 而九项平铺在 Qt 这套字号下确实偏长。**这是一处需要用户拍板的取舍**,
> 不是"验收通过";要撤回只是删掉 `SideNav` 的三个分组标题。
>
> ### 10.2 的验法(这条最容易假通过)
>
> **必须在运行时切档**(`shell.set_theme_mode(...)`),不能分别用 `--theme`
> 起三个进程 —— 后者每个都是"一开始就那个配色",**永远发现不了"切换时
> 没重算"这个缺陷**。历史上这条栽过两次,都是画布上自己画的东西没跟着换:
> 空间页 treemap 一次,导星页把 `tone_color()` 烤进 `DataTable` cell 一次。
>
> 3D 天球那条最难验,因为颜色是 `postMessage` 异步推给网页的 —— 肉眼看
> "偏暖"不足为证。验收员做了像素取样:NGC 253 的环在常规档是
> `(197,151,67)` 金橙、红光档是 `(146,52,38)` 砖红,NGC 7293 从
> `(80,136,91)` 绿变 `(104,38,27)` 红棕。**数值才证明了确实重新着色。**

> ### 心跳:连上就要跳第一拍
>
> 验收员在空间页截到两张相隔约 2 秒的图,右上角都写「○ 断开」——
> 而设备就在那儿、刚刚才连上。不是探测失败,是**顺序**:心跳循环写的是
> `while not self._hb_stop.wait(HEARTBEAT_S)`,**先等再跳** ——
> 连接成功之后的头 4 秒一次心跳都没有,`conn` 里还没有 rtt,
> 状态栏那 4 秒显示的就是「断开」。
>
> 空间页尤其容易撞上:`--auto` 一进页面就开扫大目录,人眼正盯着它,
> 而那几秒恰好落在第一拍之前。改成先跳后等,实测第一拍从 4s 提到 0.18s。
> 老 UI 的 watcher 本来就是"连上就 poke 一轮"的规矩。
