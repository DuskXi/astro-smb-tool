## 0. 已经落地的

### 0.1 定下来的四件事

| 决定 | 选的 | 为什么 |
|---|---|---|
| msgid 用什么 | **中文原文** | 源码保持可读(这个仓库注释密度很高,换成符号键就要开两个文件才知道界面上写的是什么);而且中文**永远不需要 `.mo`**,没装翻译时行为与做 i18n 之前一个字不差 |
| 机制 | **`gettext`**(标准库) | 共享层不能 import PySide6,Qt 的 `tr()` 覆盖不到那批判读文案 —— 用 `tr()` 等于一个项目两套 i18n |
| 测试怎么写 | **断言键/结构,不断言中文** | 用户 2026-08-03 定。顺带解掉一个老毛病:断言绑在中文串上,改一句文案红一片,于是没人敢改文案 |
| 老 UI 做不做 | **做**(与 Qt 一起) | 推翻了 §4 表里"不做"那一栏 —— 冻结在 2026-08-03 已改成「同步提醒」门禁,老 UI 仍在服役,是 fallback |

`astro_smb/i18n.py` 是唯一入口:`gettext`(翻)、`ngettext`(复数)、
`N_`(**只标记不翻**)、`set_language`、`available_languages`。

### 0.2 `N_()`:模块级常量必须用它

模块级的东西在 import 时求值**一次**。`KINDS = {"Light": _("亮场")}` 会把翻译
**冻在 import 那一刻的语言**上,之后 `set_language()` 再也改不动它 ——
不报错,只是界面上有一块永远是旧语言。

所以:**表里放 `N_("亮场")`,取用的地方再 `_(KINDS[k])`。**
`scripts/i18n_wrap.py` 会拒绝自动包模块级常量并单独列出来要人处理。

### 0.3 真正的收获:i18n 把「拿显示文本当身份」全炸出来了

这个仓库有一类系统性缺陷 —— **判读经过显示文本**。平时只是脆(改一句文案就
静默失效),而 i18n 是"把每个字都改一遍",于是一次性引爆。**已经炸出来的:**

| 现场 | 症状(都不报错) |
|---|---|
| `views/transfers.section_of` 比 `"排队"`,常量是 `"排队中"` | **「排队」分区永远是空的** |
| `views/records._guide_card` 在**中文短语**里找"丢星"/"失败" | 翻译后丢星那段不再标警告 |
| `views/sky3d._build_nights` 比 `"FITS 实测"` | 天球上的点静默退回 goto 请求值(与实测恒差约 21′) |
| `client.makedirs` 靠 `"已存在" in str(e)` | 一翻译,建目录开始报错 |
| `entries.ext_category` 的返回值同时是**行首符号键**与 **treemap 色号**(`crc32(类名)%8`) | 一翻译:符号全变兜底方块、每种文件颜色整体洗牌 |
| `guidequality` / 两套前端在 `findings` 里搜「恰定」判可证伪性 | 一翻译,静默变成"这个极轴数字可信" —— 而它恰恰推翻不了 |
| `autorunlog.integration_by_filter` 拿 `"未知"` 当滤镜键 | 一翻译,那一档筛不掉,徽章上多出一个空滤镜 |
| Qt `pages/transfers` 组头比 `"完成"`/`"失败"`;`widgets.GROUP_GLYPHS` 按**组名**查图标 | 计数永远 0;图标全退回一个点 |

修法一律相同:**身份与显示分家**。判读函数返回稳定键(`alt_verdict` →
`ALT_LOW`),显示是另一支函数;查表用 `xxx_id()`,显示用 `xxx()`;
状态比常量不比字面量。

> **`ext_category_id` 那条的取舍值得单说。** 身份键**故意仍是中文拼写**
> (msgid),不是 ASCII。换 ASCII 会让 `crc32` 落到别的色号上 ——
> 每种文件的 treemap 颜色都会变一次,而 §6 那批验收截图正是按现在这套色验的。
> 用 msgid 当身份与本项目"msgid 即中文原文"的约定一致,且换语言时零变化。

### 0.35 覆盖:**四层全部包完**(2026-08-05)

| 层 | 状态 |
|---|---|
| 核心库 `astro_smb/` | 包完(错误消息、CLI 输出、板解算/导星逆推的判读文案) |
| 共享层 `astro_smb_app/`(含 `views/`) | 包完 |
| Qt `astro_smb_qt/` | 包完(含类体的 `TITLE`/`SUBTITLE`、边栏、配色档名) |
| 老 UI `astro_smb_gui/` | 包完(Python 侧 + **XAML 属性值**) |

当前数量跑 `uv run python scripts/i18n_survey.py` 与
`uv run python scripts/i18n_wrap.py <目录>`(后者报"还没包的")。

**语言可以手动切**:边栏底部的下拉(只在装了不止一种语言时出现),
选择存在 `settings.json`,**切换会替用户重启** —— 界面文案是建控件那一刻
烤进去的,运行时热切要重建整棵控件树,而那时可能有后台 worker 正拿着旧控件
的引用,`on_done` 会打到已析构的 C++ 对象上。

**系统语言识别**走 `i18n.detect_language()`:`ASTRO_SMB_LANG` >
`LANGUAGE`/`LC_ALL`/`LC_MESSAGES`/`LANG` > Windows 的
`GetUserDefaultUILanguage()` > `locale.getlocale()`。
**不能只用最后一个** —— Windows 上它给的是 `'Chinese (Simplified)_China'`
这种名字,`startswith("zh")` 是 False,于是中文机器被判成"不是中文"、
兜底回中文(结果碰巧对),而英文机器上**装了 `en` 词表界面也永远是中文**。

#### XAML:属性值上包不了 `_()`

`<TextBlock Text="刷新"/>` 里那个"刷新"是 XML 属性,没地方放函数调用。
做法是在 `XamlReader.Load` **之前**处理字符串(那些 XAML 本来就是当字符串
读进来的),见 `astro_smb_gui/_xamli18n.py`:

* 只动**白名单属性**(`Text`/`Content`/`PlaceholderText`/`ToolTipService.ToolTip`
  …)—— 误翻 `x:Name` 会让 `FindName` 全线失灵,而那是静默的;
* `&#10;` 这类实体**进出对称**:msgid 里是真换行,写回去重新转义;
* **抽词表与运行时同一份判据**(`_xamli18n.msgids`),不各写一套。

### 0.4 工具链(五个脚本,各管一段)

```bash
uv run python scripts/i18n_survey.py              # 还有多少中文没进词表(按层统计)
uv run python scripts/i18n_wrap.py <目录> [-w]     # 机械包 _() / f-string → .format()
uv run python scripts/i18n_extract.py [--check]   # 源码 → locale/astro_smb.pot
uv run python scripts/i18n_build.py               # .po → .mo(uv 的 Python 没带 msgfmt)
uv run python scripts/i18n_pseudo.py              # 生成伪语言 xx_PS
```

**`i18n_wrap.py` 最重要的部分是它拒绝包什么**:模块级常量、比较操作数、
字典键/下标。这三类包进去就是新造一个 bug,所以它跳过并单独列出来要人看 ——
上面 §0.3 那张表有一半是这么捞出来的。

**伪语言是验收手段,不是翻译。** `⟦…⟧` 加壳、占位符原样保留:

```bash
uv run python scripts/i18n_pseudo.py
ASTRO_SMB_LANG=xx_PS uv run --with pyside6 python -m astro_smb_qt
```

屏幕上**没加壳的字 = 漏包了**;**行为变了 = 还有一处拿显示文本当身份**。
比人眼扫 500 处源码可靠得多,也不需要先写出一份正确的天文英文。

### 0.5 测试的语言是**钉死的**,另有一个审计口

`tests/conftest.py` 有一条 autouse fixture 把每条用例的语言钉在 `zh_CN`。

**这不是把问题藏起来,是修一个真 bug**:`astro_smb.i18n` 在 import 时按环境
挑语言,所以在此之前,**一台 `LANG=en_US` 的机器上这套测试会红一片**,
而代码一个字都没错。那种红比不红更糟 —— 它训练人忽略测试结果。

语言无关性由另外两处守:

* **判读**:`TestJudgementDoesNotGoThroughDisplayText`(用例里自己切语言);
* **界面**:伪语言跑一遍(上面 §0.4)。

想知道"还有多少断言绑着中文":

```bash
uv run python scripts/i18n_pseudo.py
ASTRO_SMB_TEST_LANG=xx_PS uv run --with pyside6 pytest tests/ -q
```

红的条数 = 还没改成"断言键/结构"的条数。**2026-08-05 已经清到 0** ——
也就是说全量测试在伪语言下和在中文下**一样全绿**。这个数只该是 0;
不是 0 就说明又有断言绑上了中文(或者产品又有一处身份走了显示文本)。

改法在 `tests/support.py` 的 `tr()`:从**同一个 msgid** 算出期望值,
两边一起变。不变量("这个输入必须选中那条消息")还在,耦合没了 ——
改一句文案不再红一片,换语言也不再全线红。

三条踩过的:

* **整条是一个 msgid 时不能比前缀。** `ZWO 卡 · 命中 {0} 项(…)` 整条被
  一起翻掉,`startswith("ZWO 卡")` 在中文下碰巧成立,换语言就不成立;
* **别拿 `tr()` 去比测试自己喂进去的假数据** —— 产品只是原样透传,没经过
  翻译,那样就变成在测翻译本身了;
* **有些"翻译失败"其实是产品的锅。** 这批断言逼出来两处:
  `volumes.kind_text` 漏包;以及更要命的 —— 最后一轮**机械清扫**把
  `entries.ext_category_id`(**身份**函数)里的 `" 文件"` 也包了,
  于是身份变成 `XYZ⟦ 文件⟧`,treemap 取色和行首符号会跟着语言洗牌。
  中文下全量测试照样全绿,是伪语言跑出来才发现的
  (`TestIdentityFunctionsStayLanguageIndependent` 现在守着)。

## 调研:一句话结论

**这个架构对 i18n 出奇地友好,但有三处真正的坑,而且都不在"翻译"本身。**

友好是因为几套前端**共用同一份视图模型**;坑在于冻结的老 UI、核心库的异常消息、
以及**测试与金标里钉死的中文**。

---

## 1. 文案住在哪

跑普查脚本会看到分层统计。按性质分成三类:

### 1.1 共享层(翻一次,三套前端同时生效)—— 最值钱

`astro_smb_app/views/` 里的**判读文案**:

| 文案 | 出处 | 为什么难翻 |
|---|---|---|
| `偏低` | browser / records | 高度角判读,阈值是有前提的经验值 |
| `欠采样` / `过采样` / `合适` | browser | 像元比例 vs 视宁的采样判读 |
| `大气质量` | browser | airmass,不是"空气质量" |
| `西垂` / `东垂` | guiding | pier side,赤道仪在中天哪一侧 |
| `已完成` / `已暂停` / `被截断` | records | 拍摄块的收尾状态 |
| `建议检查极轴` | guiding(经 ui) | DEC 漂移超阈值时的结论 |

**这些不是界面装饰,是判读结论。** 翻译的人得懂天文,否则 `大气质量` 会被翻成
air quality、`西垂` 会被翻成 west hanging。

**架构红利**:两套前端(老 WinUI3 / Qt)消费的是**同一份** `views/`,
所以这一层翻一次就够。换成各写各的,就是翻两遍还会分叉 ——
而"两边对同一份数据给出不同说法"正是这个仓库一直在防的病。

### 1.2 各前端自己的界面文案

- `astro_smb_qt/`(Qt 前端)
- `astro_smb_gui/` + 它的 `*.xaml`(老 UI)

> **调研时写的是三套前端。** Uno(`astro_smb_app/ui/` + `frontend/` 的 C#
> 渲染器)在 2026-08-03 已删除,现在只有两套。当时"C# 里没有一个字业务文案、
> i18n 完全不用碰 C#"的结论没错,只是那个前端不在了。

### 1.3 核心库的异常消息

`astro_smb/` 里含中文的字符串,**一大半是 `raise SmbClientError("…")` 的消息**,
它们会直接显示给用户(项目约定:核心库对外只抛 `SmbClientError`,message 已人类可读)。

## 2. 三处真正的坑

### 2.1 老 UI 是冻结的 —— 最贵的一条

> **这一节的结论已被推翻。** 冻结在 2026-08-03 改成了「同步提醒」门禁
> (改了要重算基线 + 在 `frontend.md` 记一笔),用户选的是**两套一起做**。
> 下面的分析仍然成立,只是选了第 2 条而不是推荐的第 1 条。

`astro_smb_gui/` 的文案量是各层里最大的,外加 `*.xaml` 里的一批属性值。

而冻结门禁(`tests/test_legacy_ui_freeze.py`)是**逐字节 sha256**,
`*.xaml` 也在冻结范围内。i18n 意味着改遍每个字符串 ——
**等于把冻结政策整个作废**。

**现实选项只有两个:**

1. **老 UI 不做 i18n**(推荐)。它本来就是 Windows 专属的 fallback,正在被
   跨平台前端逐页替换。为一个正在退役的前端付这么多改动不划算。
2. 接受"为 i18n 一次性解冻",重算基线并在 `frontend.md` 记一笔。

### 2.2 核心库不能 import 前端设施

核心库那些异常消息要翻,但 `astro_smb/` 是**最底层**,
`test_shared_layer_never_imports_a_frontend` 守着分层。

- **标准解法**:核心库抛**错误码 + 参数**,翻译在前端做。
  代价是一次不小的重构,而且会丢掉现在"消息本身已经人类可读"的好处
  (CLI 直接打印 message 就能用)。
- **折中**:用 `gettext`。它是**标准库**,不算前端依赖,不破坏分层。
  核心库用独立的翻译域(如 `astro_smb`),前端各用各的域。

### 2.3 测试与金标钉死了中文 —— 被低估的一条

- **几十个测试文件、几百处断言里直接写着中文**
  (如 `assert "Settle 无记录" in text`)。
- **金标载荷(`tests/golden/ui/*.json`)里有上千个中文字符**
  (JSON 里是 `\uXXXX` 转义的,肉眼看不出来 —— 要解码后才数得到)。

i18n 之后这些**全部会漂**。两条路:

1. 断言改成断言**结构或 key**,不断言中文字面量;金标生成时**强制 zh**。
2. 金标按语言各存一份,测试锁死在某个语言环境。

**改测试的工作量和改代码是同一个量级。** 这条不先定下来,
后面每加一条测试都会踩。

## 3. Qt 前端:现在是零,而这是个时机问题

Qt 侧目前 `tr(` 出现 0 次、`QTranslator` 0 次 —— 在按纯字符串写。

Qt 有原生的 `tr()` + Linguist(`.ts`/`.qm`)体系,但**它用不到 `views/` 上** ——
共享层不能 import PySide6(同样是分层约束)。

所以:**就算 Qt 侧用 `tr()`,那批共享判读文案还是得走另一套机制** ——
一个项目两套 i18n 体系,正是这个仓库一直在防的"双实现"。

**结论:Qt 侧不要用 `tr()`,全项目统一走 `gettext`。**
这个决定越早越便宜 —— 等九页写完再统一,成本翻倍。

## 4. 建议的方案(现已实施,见 §0)

**单一机制 = `gettext`**:标准库、无新依赖、跨前端通用、不破坏分层。

范围建议:

| 层 | 做不做 | 理由 |
|---|---|---|
| `astro_smb_app/views/` | **必做** | 收益最大,一次翻译三套前端生效 |
| `astro_smb_qt/` | **必做** | 面向用户的那一层 |
| `astro_smb/` 异常消息 | 做,用独立域 | 会显示给用户;`gettext` 不破坏分层 |
| `astro_smb_gui/` + `*.xaml` | ~~不做~~ → **做** | 冻结已改成同步门禁;它仍在服役,是 fallback |
| ~~`frontend/`(C#)~~ | — | Uno 前端 2026-08-03 已删除 |

**前置问题(必须先定)**:金标与测试的语言绑定策略。见 §2.3。

**建议的落地顺序**:先定测试策略 → 再抽 `views/` → 再抽两套新前端 →
最后核心库异常。倒过来做会在中途把测试全弄红。

## 5. 没调查的

- 具体翻成哪些语言、谁来翻(天文术语需要懂行的人)
- 复数/性数变化:中文没有,英/俄/阿拉伯语有。
  现在的文案里有 `N 帧` / `N 个共享` 这类,需要 `ngettext`
- 日期时间的本地化格式(现在是 `%m-%d %H:%M`,与语言无关但与地区习惯有关)
- 右到左(RTL)布局 —— 两套前端都没考虑过
- 字体覆盖:CJK 字形在 Skia/Qt 上的可用性(macOS/Linux 尤其)
