# 前端架构与老 UI 冻结

## 分层

```
astro_smb            核心:SMB/本地后端、FITS、天文、日志、板解算、导星逆推验证
   ↑
astro_smb_app        共享应用层:设备记录、缓存、传输队列、预览、日志聚合、卷枚举
   ↑                 (不 import 任何前端)
   ├── astro_smb_gui        WinUI3 / win32more —— Windows 原生,**并且是界面原型**
   └── astro_smb_qt         PySide6 / Qt —— **跨平台交付**(含 Windows)
```

`astro_smb_app` 里那九个模块**原本住在 `astro_smb_gui/` 里**,一行 win32more
都不 import。B2 把它们移出来,是为了让新前端不必反向依赖一个已冻结的包。
`astro_smb_gui/` 侧留了同名 shim(`sys.modules` 别名),所以老 UI 的 import 行
一个字节没改,而且拿到的是**同一个模块对象** —— 这点是硬要求:`metacache`
持有全局 sqlite 连接与一把锁,两份状态会互相踩。

## 方向(2026-08-03,用户定)

> **Windows 上双 UI(WinUI3 + Qt),跨平台走 Qt。
> UI 以 WinUI3 为原型开发,再同步实现到 Qt。Uno 那套判为不成功。**

也就是说三套前端的角色重新划定:

| | 角色 |
|---|---|
| `astro_smb_gui`(WinUI3) | **原型 / 范本**。新界面先在这里成形 |
| `astro_smb_qt`(PySide6) | **跨平台交付**。照 WinUI3 同步实现,含 Windows |
| ~~`astro_smb_app/ui` + `frontend`(Uno)~~ | 判为不成功,**已删除**(标签 `archive/before-uno-removal`) |

这个判断有实证支撑:Qt 这套是**照着 WinUI3 逐页复刻**做出来的,
`docs/qt-final.md` 走完九页独立验收后 103 条过 —— "先有范本再复刻"这条
路径本身被验证是有效的。Uno 那套走的是另一条路(通用渲染器 + 词表),
最贵的 bug 全出在"图元在词表里 ≠ 渲染器实现了它"。

### 冻结已解除,门禁改成「同步提醒」(用户 2026-08-03 拍板)

冻结当初要解决的是"新前端还没追平时,老 UI 别再往前跑"。Qt 追平之后
那个前提不成立了,而且"以 WinUI3 为原型"要求新功能**必须**先加在它上面。

所以政策改成:

- **老 UI 可以自由加新功能、改文案、调布局** —— 它是原型;
- `tests/test_legacy_ui_freeze.py` 与 `legacy-ui.sha256` **保留**,但含义变了:
  改了就变红,红了就去重算基线**并在下面的变更表里记一笔**;
- 那一笔**必须写清楚同步状态**:已经同步到 Qt,还是本轮不同步、原因是什么。

真正要防的风险已经从"老 UI 乱动"变成**两套 UI 悄悄分叉**,而分叉是
不报错的 —— 这正是门禁留着的理由。

## 门禁机制(原「老 UI 冻结」)

`astro_smb_gui/` 是**功能完整、正在服役**的那套界面,现在还是**界面原型**。
门禁保留,作用见上一节:**改了要记一笔,并写清同步到 Qt 没有。**

机制本身没变:

- 门禁在 `tests/test_legacy_ui_freeze.py`,基线在 `legacy-ui.sha256`(37 个文件)。
  `web/` 下的 JS/CSS/HTML 曾经也在里面,B10 把它移到共享包后由那边负责 ——
  它现在是两套前端共用的资产,不再属于"老 UI 的冻结面"。
- 改了老 UI → 测试变红 → 你必须显式重算基线并在下面的变更表里记一笔。

### 逃生口

uv run python -c "import sys; sys.path.insert(0,'tests'); import test_legacy_ui_freeze as t; print(t.build_manifest(), end='')" > docs/architecture/legacy-ui.sha256

## 与老 UI 的布局对齐(B16)

九页 + 外壳都对着**真机截图**逐项比过了。老 UI 的参考截图是 2026-08-01 拍的
(`--host 192.0.2.227`,各页各起一次进程用 `ASTRO_SMB_GUI_START_PAGE` 直达)。

结构上改动最大的是外壳:我第一版把导航做成了顶部一排按钮,而老 UI 是**左侧
竖直的一列**。顺序、文案、图标位置现在全对齐;顶部连接栏与底部常驻传输队列条
同理。

对齐过程中修的东西**多数不是观感,是判读**:

| 页 | 修的是什么 |
|---|---|
| 导星 | 整体 RMS 用了各段简单平均,被一段 22.96″ 的短尝试拉到 1.89″(加权是 0.92″)；7543 帧画折线只是噪声,老 UI 在 >2 帧/像素时切包络视图 |
| 记录 | `type_stats` 是**方法**不是属性 —— 异常抛在 worker 的 `finally: push()` 里,线程当场死掉,页面永远停在"正在解析" |
| 浏览 | `ResourceTable` 空表是 falsy,`if self.resources:` 让第一份资源永远发不出去(缩略图说明在、图不在) |
| 空间 | 顶行把面包屑当二元组解包,两个字的目录名会被拆开、其余长度直接 ValueError |
| 扫描 | 卡片改紧凑两行时把 IP 那行漏了 —— 要连哪台靠的是地址 |

新增门禁(都做过回退验证):`push()` 不许让建树异常带走调用线程、记录页要能吃下
`.tmp/` 的真日志、九页 × 忙态/空态/有数据态全过一遍、加权 RMS 不被短段带偏、
不许对 `ResourceTable` 做真值判断、并发下拉背后的方法必须真的存在。

B18 把这两样也补上了:

- **导星页按拍摄目标分组**,默认全折叠。走的是 `views.guiding._prepare` —— 老 UI
  一直在用的那条流水线,分组/折叠/汇总全在里面。我第一版绕过它自己拼了个平铺
  列表:真机 123 段里 103 段是几帧就结束的短尝试,真正想看的那几段被埋在里面。
  顺带把导星页也改成走 logstore(和记录页同一份 LogData)—— 分组要按拍摄目标
  对齐,那要 Autorun 侧的块;两条路径各自下载同一批文件还会撞 `.part`。
- **天球放大遮罩 + 时刻滑杆**。页内覆盖层不是对话框(ContentDialog 内容上限
  约 548px 会把大图裁掉一角);滑杆走整夜任意时刻,而**整图必须同一时刻**。

同时实现掉的三个"在词表里但渲染器没做"的:`card` 的底色(注释一直写着"再加
卡片的边框与背景",但 Apply 里从来没有 —— 遮罩因此是透明的,两层文字叠在一起)、
`slider` 的最小宽度(横向栈里期望宽度几乎为 0,真机上塌成一个圆点,看得见拖不动)。

## macOS / Linux

新前端本来就是为了跨平台才做的,B17 把跨平台那几处分叉收了口:

- **数据目录**走 `astro_smb.paths` —— Windows 仍是 `%LOCALAPPDATA%/AstroSmbTool`
  (一个字节没变,那底下有用户的设备记录、8 MB 底图、35.6 MB 星表);
  macOS 分成 `~/Library/Application Support` 与 `~/Library/Caches`。
- **`curl.exe` → `curl`**、`CREATE_NO_WINDOW` 在别的平台是 0。
- **WebView2 预加载**在非 Windows 早退 —— 不早退直接 `ctypes.WinDLL` 属性错误,
  而它在 `ensure_assets()` 里,会把整个资产引导带走(天球页永远白屏)。

门禁在 `tests/test_cross_platform.py`,其中最实在的一条是**把 `win32more` 的
import 整个屏蔽掉**,再把 Qt 的九页全部构建一遍 —— 在 Windows 上开发时
那个包一直躺在环境里,任何不小心加进来的依赖都要等到有人在 mac 上
`uv sync` 才会暴露。(Uno 删除后这条转指 Qt,守的性质没变。)

上手命令见 `START-HERE-macOS.md`。**尚未在真 mac 上跑过** ——
那些门禁是护栏,不是实机验证。

## 为什么这次要有门禁

上一轮是**只写文档**的。`docs/architecture/frontend-migration.md`(已删)白纸黑字
写着 "`astro_smb_gui` 是迁移基线,不再修改,也不会进入 wheel、sidecar、安装器或
新前端的导入图"。实际情况:它既在 wheel 里、又是默认入口、还被改了 8 次;
那份 `legacy-ui.sha256` 对 7 个文件早已对不上,而且**没有任何代码在读它** ——
一个纯孤儿文件。

文档挡不住漂移,红色的测试才挡得住。这条门禁本身也做了反证:改老 UI 一个字节、
或新增文件不重算基线,两条路径都确实变红。

### 拖出到资源管理器:不做,而不是没做完

老 UI 的 `dragout_ole.py` 在 Python 里实现了 COM `IDataObject`/`IStream`,
资源管理器松手时同步读流,真正的"拖拽即下载"。**这东西没有跨平台等价物** ——
macOS 是 `NSFilePromiseProvider`,Linux 是 XdndDirectSave,三套接口三种语义。
新前端给的是"下载"与"复制路径",两条在三个平台上行为一致;Windows 用户要拖出,
老 UI 那套还在服役。把它做成半残的三份实现,比不做更糟。
